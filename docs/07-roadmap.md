## 内容生产顺序建议

不要按模块字母序做，按「能讲通一条端到端故事」做：

1. **SD 销售订单 → 交货 → 开票**（O2C 主干）；
2. **MM 采购申请 → 采购订单 → 收货 → 发票校验**（P2P 主干）；
3. **FI 应收 / 应付 / 总账**（把 O2C、P2P 的财务后果接上）；
4. **EWM / WM 仓库执行**（补齐交货的下一步）；
5. **PP / QM**（生产与检验）；
6. **CO / PS / PM / CS / HR / ABAP**（按需要扩展）。

每完成一条链，就在 `scenes/` 里补一个端到端视图，验证「跨模块」是否真的成立。

## 风险与应对

| 风险 | 触发信号 | 应对 |
| --- | --- | --- |
| 内容拖慢开发 | 一直在写 YAML，没有可看的界面 | Phase 0 后先冻结 2 个流程，优先做 UI |
| 画布过度设计 | 动画/布局反复改，核心路径没通 | 以「3 次点击到达 VA01」为硬指标 |
| 范围膨胀 | 想加 3D、AI 问答、协作 | 写入「以后再说」，不进入当前里程碑 |
| 内容不可信 | 大量无来源条目 | `verified` 门槛 + 审核清单 |
