# 02 · 信息架构与交互设计

> 目标：用户在任何缩放级别都能回答三个问题——**我在哪？这里有什么？下一步去哪？**

## 1. 四层视图

```text
L0 系统全景 Universe
   │  12 个模块 + 4 条主干价值流丝带 + 右上角 10 条价值流目录
   │  click module
   ▼
L1 模块工作区 Module Workspace
   │  模块内的业务流程卡片、阶段、上下游边界
   │  click process
   ▼
L2 流程画布 Process Canvas
   │  步骤节点 + 有向边 + 跨模块门户
   │  hover step → Hover 卡；click step → 检查器
   ▼
L3 对象聚焦 Object Focus
    │  spotlight 使用该对象的步骤 + 对象关系 + 代码
    ▼
   检查器 / 对象详情
```

| 层级 | 场景 ID 示例 | 默认缩放 | 画布上出现 | 主要动作 |
| --- | --- | --- | --- | --- |
| L0 全景 | `universe` | 0.7 | 模块卡片、E2E 流程丝带、图例 | 点击模块 / 流程 |
| L1 模块 | `module-sd` | 0.9 | 业务流程卡片、阶段分组、跨模块门户 | 点击流程 / 门户 |
| L2 流程 | `process-sd-order-management` | 1.0 | 步骤节点、顺序/分支边、对象数徽标 | Hover、点击、打开检查器 |
| L3 对象 | 叠加在 L2 上 | 1.0 | 相关步骤高亮、对象关系边、代码预览 | 切换对象、查看代码、跳步骤 |

当前实现：打开对象检查器后，当前场景内使用该对象的步骤与对象会高亮，其他步骤/对象淡化；关闭检查器即恢复。

层级之间不是页面跳转，而是**同一画布的相机运动 + 场景替换**。用 300–450ms 的推进感保持空间连续。

> 当前实现中，ABAP 模块使用 `object` 节点构成“开发地图”，与其他模块的流程卡片视图共用同一个画布与检查器；移动端自动切换为纵向卡片列表。

## 2. 导航模型

### 2.1 URL 即状态

GitHub Pages 没有服务端路由，使用 hash 路由，保证深链接与刷新可用：

```text
#/                               → L0 全景
#/m/sd                           → SD 模块工作区
#/m/sd/p/sd-order-management     → SD 订单管理流程
#/f/order-to-cash                → O2C 跨模块流程视图
#/o/tcode/VA01                   → 打开对象检查器（叠加在当前场景）
#/m/sd/p/sd-order-management?step=sd-va01-create-sales-order&tab=objects
```

规则：

- 场景（scene）是路由的第一等公民；检查器是叠加状态，不单独换页；
- 返回键回退到上一个场景与相机位置；
- 每个场景记住上次的视口（sessionStorage），刷新后恢复；
- 分享链接包含 `step` / `object` 时，打开后自动聚焦并播放一次定位动画。

### 2.2 位置感组件

| 组件 | 位置 | 作用 |
| --- | --- | --- |
| 面包屑 | 顶部左 | `全部模块 / SD 销售与分销 / 订单管理`，每级可点 |
| 左侧导航树 | 左侧（桌面） | 模块 → 流程 → 步骤，当前节点高亮，同级切换 |
| 对象类型筛选 | 导航树底部 | T-Code / 表 / BAPI / CDS / OData，高亮相关步骤与对象 |
| 缩放级别指示 | 右下（迷你地图上方） | 显示 `系统 / 模块 / 流程 / 步骤`，可点击回到上层 |
| 迷你地图 | 右下 | 当前视口在场景中的位置 |
| 流程进度胶囊 | 顶部中 | `O2C · 第 2 步 / 共 5 步`，点击展开流程步骤列表 |
| 跨模块兄弟 | 节点 Hover 卡 / 检查器 | `在 MM、EWM 中也出现`，点击跳转 |
| Hover 钉住 | 节点旁的预览卡 | 固定对象/步骤卡，查看相关步骤或对照画布 |
| 故事模式 | O2C 场景栏 + 底部浮层 | 6 步 guided story，上一步/下一步、URL 记录 |
| 流程对比 | 流程场景栏 + 模态 | 当前 A vs 另一 B：共同/独有对象与步骤差异 |
| 最近访问 | 场景栏 | sessionStorage 保留 5 个场景，一键回跳 |
| 访问轨迹 | 左下（可折叠） | 最近 5 个场景，支持快速返回 |

### 2.3 相机与过渡

- 进入下一层：以被点击节点为中心 `fitView` 到新场景的目标节点，旧场景淡出；
- 返回上一层：相机回到离开时的视口，而不是默认位置；
- 同一实体跨场景跳转（如 VA01 在 SD 流程与 O2C 流程中的两次出现）：使用**共享元素动画**，源节点放大 → 目标节点从同位置展开；
- 所有相机动画使用 `easeInOutCubic`，450ms；减少动态时改为瞬时切换 + 200ms 淡入。
- 实现上，场景切换通过 `fitView({ padding: {x: 40, y: 36}, duration: 450 })` 完成，内容栏与场景栏不覆盖画布。

## 3. 语义缩放（Semantic Zoom）

同一场景内，缩放改变**信息密度**，不改变节点位置。

| 缩放区间 | LOD | 节点显示 | 边显示 |
| --- | --- | --- | --- |
| `< 0.6` | 远 | 色块 + 名称 + 图标 | 仅主干边，无标签 |
| `0.6 – 0.95` | 中 | 名称 + 一句话摘要 + 对象数 | 主干边 + 关键字标签 |
| `0.95 – 1.4` | 近 | 名称 + T-Code + 对象类型 chips | 全部边 + 标签 |
| `> 1.4` | 特写 | 增加代码预览、最近来源、跨模块提示 | 依赖边、数据边显现 |

实现要点：

- 只在跨越阈值时更新 `data-lod`，不要每帧 setState；
- 用 CSS 控制显隐（`opacity` / `display`），节点尺寸保持稳定，避免布局抖动；
- 高 LOD 才请求对象详情与代码，低 LOD 只用预生成的摘要；
- 缩放级别与「我在哪」指示器联动。

## 4. 节点与边的语义

### 4.1 节点类型

| 类型 | 出现层级 | 视觉 | 点击行为 |
| --- | --- | --- | --- |
| `module` | L0 | 大卡片，模块色，图标，流程数 | 进入 L1 |
| `flow` | L0 / L1 | 丝带 / 标签 | 进入跨模块流程场景 |
| `process` | L1 | 卡片，阶段色条，步骤数 | 进入 L2 |
| `step` | L2 | 卡片，序号或 T-Code，对象数徽标 | 打开检查器 |
| `object` | L1（ABAP 开发地图） | 类型徽标 + 技术名 + 关系数 | 打开对象检查器 |
| `portal` | L1 / L2 | 半透明、虚线边框、目标模块色 | 跳到另一个场景的同源节点 |
| `group` | L1 / L2 | 大圆角背景 + 标题 | 不作为交互目标 |
| `note` | 任意 | 便签样式 | 打开说明 |

### 4.2 边类型

| 类型 | 含义 | 样式 |
| --- | --- | --- |
| `sequence` | 流程的下一步 | 实线 + 箭头，模块色 |
| `handoff` | 跨模块交接（单据 / 物料 / 凭证） | 虚线 + 流动动画 |
| `data` | 读取或写入的数据关系 | 点线，灰色 |
| `dependency` | 开发对象依赖 | 细线，低对比度 |
| `portal` | 指向另一个场景的同源节点 | 渐变虚线，悬停时高亮 |

边标签只在 LOD ≥ 近 时显示；主干边可以有 1–3 个字的动词标签（`创建`、`过账`、`开票`）。

## 5. Hover 卡（轻量预览）

### 5.1 触发与收起

- Hover 节点 120ms 后出现；离开节点 180ms 后收起；
- 卡片自身 Hover 时不收起（可点击内部对象）；
- 快速扫过多个节点时，只保留最后一个；
- 键盘聚焦节点时立即显示，并标记为「固定」；
- 触摸设备不显示 Hover 卡，点击直接打开检查器（或底部抽屉）。

### 5.2 内容层级

```text
┌─────────────────────────────────────┐
│ ● SD   创建销售订单            VA01 │  ← 模块色条 + 标题 + T-Code
│ 销售订单的入口，确定客户、物料、     │  ← 一句话说明
│ 数量、价格与交货日期。               │
│                                     │
│ 开发对象 7                          │
│ [T-Code] [表×3] [BAPI] [增强] [CDS] │  ← 类型 chips，可点击
│                                     │
│ 代码预览                            │
│ ┌─────────────────────────────────┐ │
│ │ CALL FUNCTION 'BAPI_SALESORDER… │ │  ← 5 行，语法高亮
│ └─────────────────────────────────┘ │
│                                     │
│ 在 MM · EWM 中也有出现 →            │  ← 跨模块提示
│ [打开检查器]  [聚焦此步]             │
└─────────────────────────────────────┘
```

原则：

- 只给 3–5 个线索，不把检查器塞进 Hover；
- 对象 chips 按类型分组，点击 chip 进入对象聚焦；
- 代码预览默认折叠为 5 行，点击展开到检查器；
- 卡片最大宽度 360px，最大高度 420px；
- 不遮挡当前节点：优先右侧，其次左侧，再上/下，最后用固定面板。

### 5.3 性能

- 节点只携带摘要（标题、T-Code、对象计数、类型列表）；
- `pointerenter` 后 60ms 预取对象详情；
- 代码预览按需请求，不在首屏加载；
- Hover 卡使用 `@floating-ui/react` 定位，避免布局抖动。

## 6. 检查器（完整详情）

右侧抽屉，宽度 440–560px，可拖拽调整；不遮挡画布中心，保留上下文。

```text
┌──────────────────────────────────────────────┐
│ 创建销售订单  VA01                    [×]   │
│ SD · 订单管理 · O2C 第 2 步                  │
├──────────────────────────────────────────────┤
│ 概览 │ 开发对象 │ 代码 │ 跨模块 │ 来源       │
├──────────────────────────────────────────────┤
│ 作用：……                                     │
│ 输入：客户、物料、数量、价格、交货日期       │
│ 输出：销售订单号、订单状态                   │
│ 前置：报价 / 客户主数据                      │
│ 后置：ATP 检查 → 交货                       │
│                                              │
│ 开发对象（按类型分组，可折叠）               │
│  T-Code  VA01                                │
│  表      VBAK · VBAP                         │
│  BAPI    BAPI_SALESORDER_CREATEFROMDAT2      │
│  增强    MV45AFZZ · BADI_SD_SALES            │
│  CDS     I_SalesOrder                        │
│  OData   API_SALES_ORDER_SRV                 │
└──────────────────────────────────────────────┘
```

Tab 规则：

| Tab | 内容 |
| --- | --- |
| 概览 | 作用、输入/输出、前置/后置、业务规则、常见坑 |
| 开发对象 | 按类型分组的对象列表，点击进入对象详情 |
| 代码 | 示例代码 + 行内注解 + 复制按钮 |
| 跨模块 | 同源步骤在其他模块/流程中的出现，点击跳转 |
| 来源 | 官方文档、版本、核对日期、审核状态 |

交互：

- 打开检查器时 URL 增加 `step` / `object` 参数；
- 按 `Esc` 关闭；焦点回到原来的节点；
- 打开时画布轻微左移（如果检查器会遮挡选中节点）；
- 检查器内容懒加载，切换 Tab 不重新挂载画布。

## 7. 跨模块：同一流程如何出现在多个模块

### 7.1 问题

`VL01N 创建交货` 同时属于 SD（交货）、LE（物流执行）、EWM（仓库执行），也可能出现在 O2C 与 P2P 的跨模块流程中。如果每个模块各存一份内容，事实会漂移。

### 7.2 方案：唯一节点 + 多次出现

```text
content/steps/sd/sd-vl01n-create-delivery/step.yaml
  id: sd-vl01n-create-delivery
  primaryModule: sd
  modules: [sd, ewm]
  processes: [sd-order-management]
  flows: [order-to-cash]

scenes/module-sd.scene.yaml       → node(ref: step:sd-vl01n-create-delivery)
scenes/ewm-module.scene.yaml     → node(ref: step:sd-vl01n-create-delivery)
scenes/flow-order-to-cash.scene.yaml  → node(ref: step:sd-vl01n-create-delivery)
```

同一个 `step` 被多个场景引用，**布局各自独立，事实只有一份**。构建脚本会生成：

- `occurrences[stepId] = [{ sceneId, nodeId, moduleId }]`；
- 每个步骤的「在其他模块中」列表；
- 每个场景的 portal 节点（如果场景希望显式显示出口）。

### 7.3 门户（portal）节点

在 L1/L2 画布边缘显示半透明节点：

```text
┌───────────────────────┐
│ 在 EWM 中继续 →       │
│ 仓库执行 · 3 个步骤   │
└───────────────────────┘
```

点击后：相机推进 + 场景切换，并高亮同源步骤；返回时恢复原来的视口。

### 7.4 跨模块关系类型

| 类型 | 例子 | 展示 |
| --- | --- | --- |
| `handoff` | SD 交货 → EWM 仓库任务 | 流动虚线 + portal |
| `shared-object` | 同一张 `MSEG` 被 MM 收货与 SD 发货过账写入 | 对象检查器中的「也被使用」 |
| `master-data` | 客户主数据、物料主数据 | 虚线连到主数据节点 |
| `accounting-impact` | 发货过账生成 FI 凭证 | 跳到 FI 的过账步骤 |
| `org-unit` | 工厂、库存地点、销售组织 | 检查器中的组织上下文 |

## 8. 视觉语言

### 8.1 画布

- 浅色底：`#F4F6F9`，点阵网格 + 极浅径向光晕；
- 卡片：`#FFFFFF`，1px `#E2E8F0` 边框 + 柔和阴影，模块色只用于左侧色条、图标与浅色光晕；
- 模块色不是 SAP 官方色，而是 UI 识别色，需满足 4.5:1 对比度；
- 背景不抢戏：网格透明度 ≤ 6%，光晕 ≤ 8%；暗色模式作为后续可选项。

### 8.2 字体与字号

- 界面：Inter + Noto Sans SC；等宽：JetBrains Mono；
- 画布节点标题 14–16px，正文 12–13px，标签 11px；
- Hover 卡标题 15px，检查器正文 13–14px；
- 不使用全大写英文长标题（可读性差）。

### 8.3 动效 tokens

| Token | 值 | 用途 |
| --- | --- | --- |
| `motion.instant` | 90ms | Hover 反馈、按钮 |
| `motion.fast` | 150ms | 淡入淡出、chips |
| `motion.base` | 250ms | 面板、卡片 |
| `motion.slow` | 450ms | 层级切换、相机 |
| `motion.flow` | 900ms 循环 | 边流动 |
| `ease.standard` | `cubic-bezier(.2,.8,.2,1)` | 大部分过渡 |

`prefers-reduced-motion: reduce` 时：相机瞬移、边不流动、卡片无位移，只保留 150ms 透明度变化。

## 9. 空态、加载态与首次进入

- **首次进入**：3 步引导（拖动 / 缩放 / 点击模块），可跳过；
- **加载场景**：骨架卡片 + 渐进淡入，不用全屏 spinner；
- **空模块**：显示「待补充」卡片 + 贡献指南链接，而不是空白画布；
- **无搜索结果**：给出最接近的 3 个模块 / 流程，而不是一句「无结果」；
- **错误**：内容引用失败时显示占位节点与错误码，便于定位（开发模式下显示详情）。

## 10. 可访问性

- 画布节点可 Tab 聚焦，方向键在节点间移动（基于空间位置），Enter 打开；
- 层级切换时 `aria-live="polite"` 播报「已进入 SD 模块，共 6 个流程」；
- 所有图标按钮有 `aria-label`；
- 颜色不是唯一编码：模块同时有图标与缩写；
- 焦点环 2px，对比度 ≥ 3:1；
- 触控目标 ≥ 44×44px；移动端用底部抽屉代替 Hover 卡。

## 11. 移动端

- L0/L1 保持画布，但默认 `fitView` 到当前模块；
- L2 改为纵向流程列表 + 可展开步骤卡（画布仍可切换）；
- 检查器变为全屏底部抽屉（80% 高度）；
- 隐藏迷你地图与访问轨迹，保留面包屑与搜索。
