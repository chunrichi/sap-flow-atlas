# ADR-0001 · 使用「唯一内容图 + 多份视图布局」

- 状态：Accepted
- 日期：2026-11-24
- 决策者：项目发起人 / 内容负责人
- 相关文档：[03 数据模型](../03-data-model.md)、[04 目录结构](../04-directory-structure.md)、[02 信息架构](../02-information-architecture.md)

## 背景

SAP 的业务流程天然跨模块。`VL01N 创建交货` 同时出现在 SD、LE、EWM 的语境里；`MIGO 收货` 同时服务采购、生产、库存；一张 `MSEG` 被多个模块写入。

如果按「模块目录」各存一份流程与对象，会遇到三个问题：

1. **事实漂移**：SD 文档说 VA01 写入 3 张表，MM 文档说 2 张，用户不知道信谁；
2. **维护成本**：同一对象改一次要改 N 处；
3. **无法回答跨模块问题**：这张表还被谁用？这个步骤在其他模块怎么走？需要跨目录 join，而目录本身没有关系。

如果只做一张「全局大图」，又会遇到：节点过多、布局爆炸、无法按模块导航、加载慢。

## 决策

采用**三层分离**：

```text
① 内容图（canonical graph）
   模块 / 流程 / 步骤 / 对象 / 代码，各一份，全局 ID。

② 视图场景（scenes）
   每个模块、每条流程、每个教学视图一份布局；
   节点只存 ref + 坐标 + 尺寸 + 强调级别。

③ 派生索引（derived indexes）
   occurrences / backlinks / search / stats，构建时生成，不手写。
```

具体规则：

- `step` 有 `primaryModule` 与 `modules[]`，归属一个主模块，但可被多个场景引用；
- `step` 的 `processes[]` / `flows[]` 是事实关系；场景只是呈现；
- 场景节点 `ref: step:<id>`，不复制标题、摘要、对象；
- 同一 `step` 在不同场景可以有不同坐标、不同强调、不同邻居；
- 门户（portal）节点显式表达「去另一个场景看同一个步骤」；
- 构建脚本生成 `occurrences[stepId]`，UI 据此显示「在其他模块中」。

## 为什么不是其他方案

### 方案 A：按模块复制内容

优点是每个模块目录自包含，编辑简单。但事实重复，无法保证一致；跨模块查询需要额外同步。**否决。**

### 方案 B：一张全局大图，按模块着色

概念上最纯粹，但 12 模块 × 数十流程 × 数百步骤无法在一屏可读；缩放会丢失标签；每次加载全图。**否决。**

### 方案 C：内容按流程组织，模块只是标签

流程复用会迫使同一对象的说明复制到多个流程；模块 owner 找不到自己的内容。**否决。**

### 方案 D：数据库 + 运行时查询

静态站点不需要后端；Git + YAML 已经提供版本、review、diff。**当前不需要。**

## 后果

### 正面

- 同一事实只有一份，改一处全站生效；
- 场景可以自由试验布局，不污染内容 diff；
- 跨模块问题（occurrences、backlinks）可在构建时回答；
- 内容可被脚本校验，也可被 AI 生成；
- 未来可以加「对象依赖图」「教学视图」而不改内容模型。

### 负面 / 成本

- 场景中的 `ref` 多一层间接，调试时需要先解析 ID；
- 场景与内容的双向一致性需要校验；
- 内容作者要理解「事实 vs 布局」的区别；
- 门户节点需要手工维护 target，暂时不能完全自动生成。

### 缓解

- `pnpm content:validate` 检查所有 ref 与双向关系；
- 提供 `scripts/new-content.ts` 脚手架，减少手写；
- 文档中用「改坐标还是改事实」的判断标准（见 03 第 8 节）；
- 后续可由 `occurrences` 自动建议 portal，人工确认后写入场景。

## 验证方式

1. 同一 `step` 被 SD 模块场景与 O2C 流程场景同时引用，修改 `step.yaml` 后两边同时变化；
2. 删除被引用的 step，构建报错并列出所有引用文件；
3. 在 SD 场景点击 portal，能跳到 EWM 场景的同一 step，且返回后视口恢复；
4. 新增一个模块场景不需要改任何内容实体。

## 备注

该决策与业界「single source of truth + multiple views」一致；SAP Signavio 的流程模型也允许同一流程被多个 value accelerator 引用，只是它不暴露底层实现。我们选择把这条原则显式化、可校验化。
